## Purpose and reading rules

This matrix records what the audited implementation did with PMM's reference-bearing structures at the revision named above. It does not restore the deleted historical inventory and does not convert its `R01`-`R28` labels into roadmap stages.

Requiredness below describes code at the audited revision, not desired policy:

- **Required**: the named producer or append boundary cannot create the promoted form without the field.
- **Optional**: omission is accepted and the event or enclosing structure can still be canonical or promoted.
- **Forbidden**: the named boundary rejects the field in that role.
- **Path-dependent**: managed and direct/public producers differ.

“Canonical” means present as a typed EventLog event. “Promoted” means consumed into a projection, retrieval result, prompt, operational state, or control-plane authority. Historical utterance preservation, canonical recording, and promotion are separate states.

## Audit scope

The matrix covers the current in-repository structures that production code dereferences or uses to govern canonical history, projections, retrieval, identity, commitments, concepts, summaries, diagnostics, or writer authority. Public/programmatic `EventLog.append` is an alternate producer for every accepted ordinary event kind. External callers and provider implementations are not a closed set.

Identifier-looking fields for which no later production dereferencer was found are recorded separately. They remain useful telemetry or history, but are not promoted reference relationships in the current implementation.

## Cross-surface policy findings

### Observed behavior

1. Writer ownership, fencing, transactional predecessor selection, and required managed projection delivery are the strongest repository-wide controls.
2. Reference content is governed unevenly. R07, R08, R17D, R25, R26, and narrow R01 prompt promotion have transactional or deterministic role checks. Most other rows rely on producer construction, optional validators, or consumer filtering.
3. Public append is fenced but remains a content-policy bypass for ordinary claims, identity adoptions, concept structures, embeddings, retrieval selections, summaries, checkpoints, and many diagnostic links.
4. Required projection delivery fails closed on exceptions, but many projections intentionally return on malformed content. Those canonical events remain preserved while the projection watermark advances.
5. Existing IDs do not establish role or semantic warrant. Current code often checks neither target kind nor same-token/CID/version/thread constraints.

### Supported inference

The current substrate can host stricter reference policies without replacing its append-only history: rejected managed structure can remain in utterance history or typed failure events while canonical promotion is withheld. That inference does not select which fields must become required or which roles are permitted.

### Unresolved policy
